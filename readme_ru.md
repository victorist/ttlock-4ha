# Управление замками TTLock в Home Assistant

[English Version](readme.md) | [Русская версия](readme_ru.md)

Данный репозиторий содержит решение для управления, создания и просмотра временных и постоянных PIN-кодов в замках TTLock через Home Assistant с автоматической проверкой доступности устройств и фактической верификацией записей в замках.

---

## 📋 Общее описание

Для управления замками TTLock используется интеграция `TTLock` (кастомный компонент `hass-ttlock`). 

Интерфейс решения состоит из трех ключевых модулей:
1. **Карточка создания PIN-кода (`ttlock_card.yaml`)**: выводится на дашборд Home Assistant. Клик по кнопке вызывает всплывающую форму ввода параметров PIN-кода с помощью компонента **Browser Mod**.
2. **Скрипт создания PIN-кодов (`ttlock_script.yaml`)**: принимает параметры из формы, конвертирует даты, проверяет доступность замков, отправляет команды на создание PIN-кодов, запрашивает список кодов через `ttlock.list_passcodes` для верификации и информирует пользователя о статусе каждого замка.
3. **Карточка и скрипт просмотра PIN-кодов (`ttlock_passcodes_card.yaml` и `ttlock_list_script.yaml`)**: позволяют выбрать любой замок и вывести аккуратную табличную форму со всеми зарегистрированными в замке PIN-кодами, их статусом (`🟢 Активен` / `🔴 Истёк`) и сроком действия.

## 📁 Структура файлов

* [`ttlock_card.yaml`](ttlock_card.yaml) — конфигурация карточки создания PIN-кода через `browser_mod.popup`.
* [`ttlock_passcodes_card.yaml`](ttlock_passcodes_card.yaml) — конфигурация карточки запроса и просмотра списка PIN-кодов замка через `browser_mod.popup`.
* [`ttlock_script.yaml`](ttlock_script.yaml) — основной скрипт Home Assistant для генерации PIN-кода, каскадной обработки замков и верификации.
* [`ttlock_list_script.yaml`](ttlock_list_script.yaml) — скрипт Home Assistant для получения и отображения HTML-таблицы текущих PIN-кодов выбранного замка.
* [`readme.md`](readme.md) — документация проекта на английском языке.

## 🚀 Основной функционал и возможности

* **Просмотр всех PIN-кодов замка**: возможность в один клик получить и просмотреть полный список паролей замка (имя владельца, цифровой код, срок действия, статус активности) во всплывающем окне `browser_mod.popup`.
* **Автоматическая адаптация дат**: поддерживает передачу дат в ISO-формате и в миллисекундах (Unix timestamp) от `browser_mod`, автоматически приводя их к формату `YYYY-MM-DD HH:MM:SS`.
* **Предварительная проверка доступности (Online / Offline)**: перед отправкой команд скрипт проверяет состояние замка в Home Assistant (`states(lock_entity) not in ['unavailable', 'unknown']`). Если замок недоступен (офлайн/отключен шлюз), попытка создания пропускается, а замок получает статус `⚠️ Замок недоступен`.
* **Фактическая верификация (list_passcodes)**: вместо того чтобы предполагать успешность отправки команды, скрипт вызывает сервис `ttlock.list_passcodes` (возвращающий `response_variable`), считывает список существующих PIN-кодов и проверяет наличие созданного кода.
* **Каскадная обработка с паузами**: при создании PIN для квартиры из группы `Б14 1xx` или `Б14 2xx`, код автоматически дублируется на связанные замки (Подъезд 1, Подъезд 2, Калитка) с фиксированными паузами в **20 секунд** для предотвращения конфликтов и перегрузки шлюзов.
* **Двойное информирование**:
  - **Динамические всплывающие окна (`browser_mod.popup`)** на устройстве пользователя.
  - **Системное уведомление (`persistent_notification.create`)** со сводным результатом по всем обработанным замкам.

## 🛠 Статусы выполнения операции

По каждому замку выводится один из трех чётких статусов:
* `✅ Подтверждён` — замок был онлайн, команда выполнена, наличие PIN-кода подтверждено сервисом `list_passcodes`.
* `❌ Не создан` — замок был онлайн, команда была отправлена, но код не обнаружен при проверке списка PIN-кодов.
* `⚠️ Замок недоступен` — замок находится в состоянии `unavailable` или `unknown` (нет связи со шлюзом), команда не отправлялась.

## 📖 Подробная техническая документация и принцип работы

### 1. Исследование штатных сервисов `hass-ttlock`

Проверка файлов интеграции (`manifest.json`, `services.yaml`, `api.py`, `models.py`) подтвердила наличие полного набора функций для работы с PIN-кодами без необходимости модификации кода самой интеграции.

#### `manifest.json`
* Название: `TTLock`
* Тип интеграции: `cloud_polling`
* Использование `config_flow`, зависимости `application_credentials`, `webhook`, `pydantic`.

#### `services.yaml`
Интеграция предоставляет сервис `list_passcodes`:
```yaml
list_passcodes:
  name: List passcodes
  description: Lists all passcodes for the selected lock, including their names, codes, and validity periods.
```
Сервис объявлен с `supports_response: SupportsResponse.ONLY` (возвращает результат вызова в переменную `response_variable`).

#### Структура ответа `list_passcodes`
В `api.py` при вызове `list_passcodes` отправляется запрос `lock/listKeyboardPwd` к API TTLock. Возвращаемый результат содержит список объектов `Passcode`:
* `id` — уникальный ID кода
* `passcode` — сам PIN-код (строка)
* `name` — имя/название PIN-кода
* `type` — тип PIN-кода
* `start_date` / `end_date` — время начала и окончания действия
* `expired` — флаг истечения срока

### 2. Логика проверки и подтверждения PIN-кода

Создание и проверка PIN-кода в TTLock — это две независимые операции:
1. `ttlock.create_passcode` — отправляет команду создания кода через Gateway (API `keyboardPwd/add`).
2. `ttlock.list_passcodes` — запрашивает из замка/облака список фактически сохраненных кодов (`lock/listKeyboardPwd`).

#### Почему верификация через `list_passcodes` необходима
При ошибках сети или недоступности шлюза вызов `create_passcode` может не выдать явное исключение в скрипте (или сработать с `continue_on_error: true`). Поэтому факт отправки команды не гарантирует запись PIN-кода в замок.

Схема работы скрипта:
```text
                  Вызов скрипта
                        │
         ┌──────────────┴──────────────┐
         ▼                             ▼
   Замок Online?                 Замок Offline?
         │                             │
         ├──────────────────┐          ▼
         ▼                  ▼     Показать ⚠️
  create_passcode    (пропуск)  "Замок недоступен"
         │
    Пауза 5 сек
         │
   list_passcodes
         │
 ┌───────┴───────┐
 ▼               ▼
PIN найден    PIN не найден
 ▼               ▼
 ✅           ❌
Подтверждён   Не создан
```

### 3. Обработка недоступных замков (Offline status)

Перед выполнением каких-либо действий скрипт опрашивает состояние сущности замка в Home Assistant:
```jinja2
main_is_online: "{{ states(lock_entity) not in ['unavailable', 'unknown'] }}"
```

1. **Если замок недоступен (`unavailable` / `unknown`)**:
   - Скрипт пропускает вызовы `create_passcode` и `list_passcodes` для этого замка.
   - Присваивается статус `⚠️ Замок недоступен`.
   - Выводится информационное всплывающее окно Browser Mod с предупреждением о том, что замок находится офлайн (нет связи со шлюзом).
   - Выполнение продолжается для остальных замков по цепочке (например, переход к подъезду или калитке).

2. **Если замок доступен (`online`)**:
   - Выполняется `ttlock.create_passcode` (`continue_on_error: true`).
   - Пауза 5 секунд.
   - Выполняется `ttlock.list_passcodes` (`continue_on_error: true`).
   - Ищется совпадение по номеру `target_pin` или имени `passcode_name`.
   - При успешном поиске присваивается статус `✅ Подтверждён`, иначе `❌ Не создан`.

### 4. Каскадная логика замков и временные интервалы

Для исключения гонки запросов и перегрузки шлюзов TTLock между обработкой замков установлены фиксированные паузы в **20 секунд**.

#### Сценарии работы:

1. **Замки `Б14 1xx` (Подъезд 1)**:
   - Основной замок квартиры → создание и проверка.
   - Пауза 20 секунд.
   - Замок Подъезда 1 (`lock.b14_podezd_1` / `lock.borisenko_14_podezd_1`) → создание и проверка.
   - Финальное уведомление.

2. **Замки `Б14 2xx` (Подъезд 2 и Калитка)**:
   - Основной замок квартиры → создание и проверка.
   - Пауза 20 секунд.
   - Замок Подъезда 2 → создание и проверка.
   - Пауза 20 секунд.
   - Замок Калитка (`lock.borisenko_14_kalitka` / `lock.b14_kalitka`) → создание и проверка.
   - Финальное уведомление.

3. **Остальные замки**:
   - Обработка только выбранного основного замка → создание и проверка.
   - Финальное уведомление.

### 5. Способы оповещения пользователя

Скрипт формирует два типа уведомлений:
1. **Всплывающие окна (`browser_mod.popup`)**:
   - Отображаются пошагово в браузере пользователя, вызвавшего действие.
   - Информируют о начале обработки, паузах, офлайн-статусах и итоговом результате.
2. **Системное уведомление (`persistent_notification.create`)**:
   - Фиксирует итоговый статус по всем замкам в панели Home Assistant (`notification_id: ttlock_pin_result`).

### 6. Просмотр списка PIN-кодов замка (`ttlock_passcodes_card` и `ttlock_list_script`)

Для удобного контроля созданных паролей реализован модуль просмотра списка PIN-кодов:

1. **Карточка вызова (`ttlock_passcodes_card.yaml`)**:
   - Кнопка на дашборде выводит форму выбора замка.
   - После выбора запускает скрипт `ttlock_list_script.yaml`.

2. **Обработка данных и форматирование (`ttlock_list_script.yaml`)**:
   - Запрашивает данные вызовом `ttlock.list_passcodes`.
   - Распаковывает вложенную двух уровневую структуру ответа API TTLock (`resp["passcodes"][lock_entity]`).
   - Использует **чистую HTML-таблицу** (`<table>`, `<tr>`, `<td>`) вместо разметки Markdown для предотвращения слияния строк во всплывающих окнах `browser_mod.popup`.
   - Распознает постоянные пароли (`type: permanent` или год `1970` в дате окончания) и форматирует даты временных кодов в удобный вид `ДД.ММ.ГГГГ ЧЧ:ММ`.
   - Включает интерактивную плашку **«🔍 Отладка ответа API (JSON)»** для просмотра сырого ответа интеграции при диагностике.
