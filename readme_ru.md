# Управление замками TTLock в Home Assistant

[English Version](readme.md) | [Русская версия](readme_ru.md)

Данный репозиторий содержит решение для управления, создания, просмотра и удаления временных и постоянных PIN-кодов в замках TTLock через Home Assistant с автоматической проверкой доступности устройств и фактической верификацией записей в замках.

---

## 📋 Общее описание

Для управления замками TTLock используется интеграция `TTLock` (кастомный компонент `hass-ttlock`). 

Интерфейс решения состоит из четырех ключевых модулей:
1. **Карточка создания PIN-кода (`ttlock_card.yaml`)**: выводится на дашборд Home Assistant. Клик по кнопке вызывает всплывающую форму ввода параметров PIN-кода с помощью компонента **Browser Mod**.
2. **Скрипт создания PIN-кодов (`ttlock_script.yaml`)**: принимает параметры из формы, конвертирует даты, проверяет доступность замков, отправляет команды на создание PIN-кодов, запрашивает список кодов через `ttlock.list_passcodes` для верификации и информирует пользователя о статусе каждого замка.
3. **Карточка и скрипт просмотра PIN-кодов (`ttlock_passcodes_card.yaml` и `ttlock_list_script.yaml`)**: позволяют выбрать любой замок и вывести аккуратную табличную форму со всеми зарегистрированными в замке PIN-кодами, их статусом (`🟢 Активен` / `🔴 Истёк`) и сроком действия.
4. **Карточка и скрипт удаления истёкших PIN-кодов (`ttlock_delete_card.yaml` и `ttlock_delete_script.yaml`)**: автоматически находят все PIN-коды с истекшим сроком действия и удаляют их из умного замка TTLock с реальным отображением прогресса и мгновенным обновлением таблицы.

## 📁 Структура файлов

* [`ttlock_card.yaml`](ttlock_card.yaml) — конфигурация карточки создания PIN-кода через `browser_mod.popup`.
* [`ttlock_passcodes_card.yaml`](ttlock_passcodes_card.yaml) — конфигурация карточки запроса и просмотра списка PIN-кодов замка через `browser_mod.popup`.
* [`ttlock_delete_card.yaml`](ttlock_delete_card.yaml) — конфигурация карточки очистки истёкших PIN-кодов через `browser_mod.popup`.
* [`ttlock_script.yaml`](ttlock_script.yaml) — основной скрипт Home Assistant для генерации PIN-кода, каскадной обработки замков и верификации.
* [`ttlock_list_script.yaml`](ttlock_list_script.yaml) — скрипт Home Assistant для получения и отображения HTML-таблицы текущих PIN-кодов выбранного замка с динамической кнопкой удаления истёкших кодов.
* [`ttlock_delete_script.yaml`](ttlock_delete_script.yaml) — скрипт Home Assistant для поиска и поочередного удаления истёкших PIN-кодов с отображением живого счетчика прогресса.

## 🚀 Основной функционал и возможности

* **Просмотр всех PIN-кодов замка**: возможность в один клик получить и просмотреть полный список паролей замка (имя владельца, цифровой код, срок действия, статус активности) во всплывающем окне `browser_mod.popup`.
* **Удаление истёкших PIN-кодов в один клик с живым отсчетом**: автоматический подсчет просроченных кодов, вывод красной кнопки `🗑️ Удалить истёкшие (N)` и онлайн-счётчик оставшихся кодов во время очистки.
* **Защита от сбоев интеграции (Rate Limiting)**: регулируемая пауза между запросами предотвращает отбрасывание команд шлюзом или сервером TTLock при удалении больших пачек кодов.
* **Автоматическая адаптация дат**: поддерживает передачу дат в ISO-формате и в миллисекундах (Unix timestamp) от `browser_mod`, автоматически приводя их к формату `YYYY-MM-DD HH:MM:SS`.
* **Предварительная проверка доступности (Online / Offline)**: перед отправкой команд скрипт проверяет состояние замка в Home Assistant (`states(lock_entity) not in ['unavailable', 'unknown']`). Если замок недоступен (офлайн/отключен шлюз), операция пропускается с выводом предупреждения `⚠️ Замок недоступен`.
* **Фактическая верификация (list_passcodes)**: вместо того чтобы предполагать успешность отправки команды, скрипт вызывает сервис `ttlock.list_passcodes` (возвращающий `response_variable`), считывает список существующих PIN-кодов и проверяет наличие созданного кода.
* **Автоматический каскад для связанных замков**: создание PIN-кода в замке квартиры автоматически дублирует этот же PIN-код на общий замок подъезда и калитку.

## ⚙️ Требования и зависимости

1. **Интеграция TTLock** (`hass-ttlock`): должна быть установлена и настроена в Home Assistant. Предоставляет сервисы:
   * `ttlock.create_passcode` — отправляет команду создания кода через Gateway (API `keyboardPwd/add`).
   * `ttlock.list_passcodes` — запрашивает из замка/облака список фактически сохраненных кодов (`lock/listKeyboardPwd`).
   * `ttlock.delete_passcode` — удаляет выбранный код из замка/облака (`keyboardPwd/delete`).

2. **Browser Mod**: кастомная интеграция для показа всплывающих диалоговых окон (`browser_mod.popup`) на устройствах пользователей.

## 🛠️ Установка и добавление в Home Assistant

### Вариант 1: Добавление скриптов через UI-редактор Home Assistant (Рекомендуется)

1. Откройте Home Assistant и перейдите в **Настройки** -> **Автоматизации и сцены** -> **Скрипты**.
2. Нажмите **Добавить скрипт** в правом нижнем углу.
3. В правом верхнем углу экрана нажмите меню из **3 точек** и выберите **«Изменить в YAML»**.
4. ⚠️ **ОБЯЗАТЕЛЬНО:** Выделите всё содержимое поля (`Ctrl+A` / `Cmd+A`) и **полностью удалите предзаполненный шаблон** (`sequence: []`, `alias: ...`), чтобы текстовое поле стало абсолютно пустым.
5. Скопируйте и вставьте всё содержимое файла скрипта:
   - [`ttlock_script.yaml`](ttlock_script.yaml) (для генерации PIN-кодов)
   - [`ttlock_list_script.yaml`](ttlock_list_script.yaml) (для просмотра списка PIN-кодов)
   - [`ttlock_delete_script.yaml`](ttlock_delete_script.yaml) (для удаления истёкших PIN-кодов)
6. Нажмите кнопку **Сохранить**. Идентификаторы скриптов создадутся автоматически.

---

### Вариант 2: Добавление скриптов через файл `scripts.yaml`

Если вы добавляете скрипты прямо в файл конфигурации `scripts.yaml`:

```yaml
sozdat_pin_kod_ttlock:
  !include ttlock_script.yaml

ttlock_pokazat_spisok_pin_kodov:
  !include ttlock_list_script.yaml

ttlock_udalit_istekshie_pin_kody:
  !include ttlock_delete_script.yaml
```

*Или вставьте код непосредственно в `scripts.yaml`, указав имя ключа и сделав отступ в 2 пробела для всех строк:*

```yaml
ttlock_udalit_istekshie_pin_kody:
  alias: "TTLock — Удалить истёкшие PIN-коды"
  description: "Находит и удаляет все PIN-коды с истекшим сроком действия"
  fields:
    ...
  sequence:
    ...
```

После редактирования `scripts.yaml` перезагрузите их: **Панель разработчика** -> **YAML** -> **Перезагрузить скрипты**.

### Добавление карточек на дашборд Lovelace

1. Перейдите на нужный дашборд Home Assistant.
2. В правом верхнем углу нажмите меню из **3 точек** -> **Редактировать панель** (Edit Dashboard).
3. Нажмите кнопку **Добавить карточку** (`+`) внизу экрана.
4. Прокрутите список типов карточек в самый низ и выберите **Вручную** (Manual).
5. Замените шаблонный YAML-код на содержимое одного из файлов карточек:
   - [`ttlock_card.yaml`](ttlock_card.yaml) — кнопка вызова формы создания PIN-кода
   - [`ttlock_passcodes_card.yaml`](ttlock_passcodes_card.yaml) — кнопка просмотра списка PIN-кодов
   - [`ttlock_delete_card.yaml`](ttlock_delete_card.yaml) — кнопка очистки истёкших PIN-кодов
6. Нажмите **Сохранить**.

---

### 6. Подробности работы модуля просмотра и очистки PIN-кодов (`ttlock_passcodes_card`, `ttlock_list_script` и `ttlock_delete_script`)

Для удобного контроля и очистки созданных паролей:

1. **Карточки вызова (`ttlock_passcodes_card.yaml` и `ttlock_delete_card.yaml`)**:
   - Кнопки на дашборде выводят форму выбора замка для просмотра списка кодов или удаления истёкших.

2. **Просмотр списка и динамическая кнопка удаления (`ttlock_list_script.yaml`)**:
   - Запрашивает данные вызовом `ttlock.list_passcodes`.
   - Выводит пароли в чистой HTML-таблице со статусами `🟢 Активен` и `🔴 Истёк`.
   - При обнаружении истёкших кодов (`expired_count > 0`) автоматически добавляет в нижнюю панель модального окна красную кнопку `🗑️ Удалить истёкшие (N)`.

3. **Скрипт удаления истёкших кодов (`ttlock_delete_script.yaml`)**:
   - Находит все истёкшие коды выбранного замка.
   - Показывает живое окно прогресса с онлайн-счётчиком оставшихся кодов.
   - Последовательно вызывает `ttlock.delete_passcode` с задержкой 350 мс для защиты от ограничений частоты запросов.
   - Выдерживает паузу на синхронизацию облака и автоматически перерисует обновленную таблицу со списка действующих кодов.
